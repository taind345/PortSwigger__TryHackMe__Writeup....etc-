4. SSRF Filter Bypass
│
├── Bối cảnh
│   └── Ứng dụng thường chặn SSRF bằng blacklist: cấm "localhost",
│       "127.0.0.1", "169.254.169.254"... Nhưng blacklist dễ bị qua mặt
│       vì có nhiều cách viết khác nhau của cùng một địa chỉ IP.
│
├── Blacklist Filter
│   ├── Ứng dụng chặn các từ khóa nguy hiểm
│   │   ├── Block: localhost
│   │   └── Block: 127.0.0.1
│   │
│   └── Nhược điểm: chỉ chặn chuỗi ký tự, không hiểu ngữ nghĩa IP
│
├── Bypass IP Encoding
│   │
│   ├── Decimal IP
│   │   ├── Cách hoạt động: chuyển IP thành số thập phân
│   │   ├── Công thức: 127.0.0.1 = 127×256³ + 0×256² + 0×256 + 1
│   │   ├── Kết quả: 2130706433
│   │   └── Ví dụ: http://2130706433/admin
│   │
│   ├── Octal IP
│   │   ├── Cách hoạt động: chuyển mỗi octet sang hệ bát phân (cơ số 8)
│   │   ├── 127 = 0177, 0 = 0, 0 = 0, 1 = 01
│   │   ├── Kết quả: 0177.0.0.01
│   │   └── Ví dụ: http://0177.0.0.01/admin
│   │
│   ├── Hex IP
│   │   ├── Cách hoạt động: chuyển mỗi octet sang hệ thập lục phân (cơ số 16)
│   │   ├── 127 = 0x7f, 0 = 0x00, 0 = 0x00, 1 = 0x01
│   │   ├── Kết quả: 0x7f.0x00.0x00.0x01
│   │   └── Ví dụ: http://0x7f000001/admin
│   │
│   └── Kết hợp
│       ├── 127.1 (bỏ các octet 0)
│       ├── 127.0.1 (viết tắt)
│       └── 0177.0x0.0.1 (trộn octal + hex)
│
├── URL Encoding
│   ├── Cách hoạt động: mã hóa ký tự đặc biệt thành %XX
│   ├── Ví dụ: 127.0.0.1 → 127%2E0%2E0%2E1
│   ├── Hoặc: localhost → %6C%6F%63%61%6C%68%6F%73%74
│   └── Ứng dụng: filter thấy chuỗi lạ, nhưng server giải mã ra IP thật
│
├── Case Variation
│   ├── Cách hoạt động: thay đổi chữ hoa/thường
│   ├── Ví dụ: localhost → LocalHost → LOCALHOST → LoCaLhOsT
│   └── Ứng dụng: filter so khớp chính xác "localhost" sẽ bị qua mặt
│
├── DNS Rebinding
│   ├── Cách hoạt động: dùng domain do attacker kiểm soát
│   ├── Bước 1: Domain phân giải về IP attacker (qua lần check đầu)
│   ├── Bước 2: Đổi DNS record về 127.0.0.1
│   ├── Bước 3: Server gọi lại domain → trỏ về localhost
│   └── Ứng dụng: filter thấy domain hợp lệ, nhưng thực tế trỏ về nội bộ
│
└── Các kỹ thuật bypass khác
    ├── Redirect
    │   └── Dùng server trung gian redirect đến internal IP
    ├── IPv6
    │   └── http://[::1]/admin hoặc http://[0:0:0:0:0:ffff:127.0.0.1]/
    ├── Domain kết thúc bằng dấu chấm
    │   └── http://localhost./admin
    ├── @ trong URL
    │   └── http://expected.com@127.0.0.1/admin
    ├── Subdomain của domain cho phép
    │   └── http://allowed.com.attacker.com
    └── Unicode / homoglyph
        └── Dùng ký tự Unicode giống chữ cái gốc

```
DNS Rebinding
│
├── Khái niệm cốt lõi
│   └── Lợi dụng khoảng thời gian giữa lúc server KIỂM TRA URL và lúc server GỌI URL
│       (TOCTOU - Time-of-Check to Time-of-Use)
│
├── Cơ chế hoạt động chi tiết
│   ├── Bước 0: Chuẩn bị
│   │   ├── Attacker mua domain (ví dụ: evil.com)
│   │   ├── Trỏ DNS về IP của server attacker (ví dụ: 1.2.3.4)
│   │   └── Set TTL (Time To Live) của DNS xuống rất thấp (0 giây hoặc 1 giây)
│   │
│   ├── Bước 1: Gửi payload
│   │   └── Attacker gửi URL http://evil.com/admin vào chức năng fetch của victim
│   │
│   ├── Bước 2: Server kiểm tra (Lần tra cứu DNS thứ nhất)
│   │   ├── Victim server gọi hàm kiểm tra (vd: is_safe_url())
│   │   ├── Hàm này tra cứu DNS của evil.com
│   │   ├── DNS trả về 1.2.3.4 (IP của attacker)
│   │   └── Kết luận: 1.2.3.4 là IP public, an toàn -> Cho phép request
│   │
│   ├── Bước 3: Attacker đổi DNS
│   │   ├── Ngay sau khi qua bước 2, attacker thay đổi bản ghi DNS
│   │   └── Đổi từ 1.2.3.4 thành 127.0.0.1 (hoặc 169.254.169.254)
│   │
│   └── Bước 4: Server gọi (Lần tra cứu DNS thứ hai)
│       ├── Victim server thực hiện request HTTP thực tế
│       ├── Nó tra cứu DNS lần nữa cho evil.com
│       ├── DNS lần này trả về 127.0.0.1
│       └── Server gửi request tới http://127.0.0.1/admin (SSRF thành công)
│
├── Điều kiện để thành công
│   ├── TTL (Time To Live) cực thấp
│   │   └── Để DNS cache không giữ IP cũ, buộc server phải tra cứu lại
│   ├── Server thực hiện 2 lần tra cứu DNS riêng biệt
│   │   └── (Kiểm tra 1 lần, thực thi 1 lần)
│   └── Attacker kiểm soát hoàn toàn DNS server
│       └── Có thể thay đổi IP bất cứ lúc nào
│
├── Ví dụ thực tế
│   ├── Payload gửi vào: http://evil.com/
│   ├── Lúc filter check: evil.com -> 1.2.3.4 (public IP, hợp lệ)
│   ├── Lúc server fetch: evil.com -> 127.0.0.1 (localhost, bị chặn)
│   └── Kết quả: Server đọc dữ liệu từ chính nó hoặc metadata cloud
│
├── Ứng dụng trong bypass filter
│   └── Filter thấy domain hợp lệ, nhưng thực tế request trỏ về nội bộ
│
└── Phòng chống
    ├── Resolve IP 1 lần duy nhất
    │   └── Dùng chính IP đó cho request, không gọi lại DNS
    ├── DNS Pinning
    │   └── Giữ IP đã resolve trong suốt quá trình request
    ├── Sử dụng Proxy an toàn
    │   └── Proxy kiểm tra IP sau khi resolve, không tin domain
    ├── Kiểm tra IP sau khi resolve (ở tầng socket)
    │   └── Chặn nếu IP nằm trong dải private
    └── Sử dụng DNS nội bộ (Internal DNS)
        └── Không phụ thuộc vào DNS bên ngoài cho request nội bộ
```
